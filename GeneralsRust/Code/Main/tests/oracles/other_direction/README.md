# OTHER scheduled entry-force direction regression

The public `tests/other_direction.rs` covers a Worker-only object admitted from an authored ground OTHER locomotor, then an ordinary scheduled fixed tick. Every case begins at exactly zero velocity. The intended correction concerns only the force direction retained across a turn. The current nonzero OTHER speed metric and sampling phase are separate unresolved behavior and are deliberately unchanged.

## Original authority and reproduction

`source-pins.json` pins the original files and extracted blocks. The generator executes unchanged `Locomotor.cpp:2326-2404` (`moveTowardsPositionOther`), the zero-speed forward helper, force/motive helpers, original coordinate normalization and velocity-add statements. Original line directives remain present. Object access, supplied rotation, clock, mass-one state and template access are labelled harness providers. The original engine's actual rotation, scheduler, terrain, collisions, friction and complete trajectory do not execute here.

From this directory, run `python3 generate_other_direction_oracle.py --output /tmp/new-other-direction-oracle`, then `python3 verify_other_direction_oracle.py --run /tmp/new-other-direction-oracle`. An existing C++17 compiler is used; nothing is downloaded. A portable source-only copy may supply `--source-root <root>` containing the exact pinned original paths. The generator rejects changes to the pin manifest, full source files and extracted blocks before compilation.

The frozen fixture is `../../fixtures/other_direction_original.txt`, SHA-256 `9be3c8eb2e4017e44a285973f7059c2e4c6514fa6d416532cd1dd80459587734`. `fixture-schema.json` describes its 47 columns. Nine scenarios appear in each of two distinct scalar lanes. The raw-frame lane uses original speed/rate conversions. The host-impulse lane supplies parsed/rebound host speed and acceleration/braking times host dt, and divides the slide factor by 30 to preserve the world-distance threshold. Original XYZ maps to host `(X,Z,-Y)`. Raw-frame velocity scaled by 30 and host-adapted velocity must not be conflated because f32 round trips differ. The displacement column is a labelled harness projection, not an original engine pose update.

The primary case begins facing +X, turns 90 degrees toward host +Z, and retains +X force in the original. Thirty-degree and reflected targets, a different entry heading, a nonzero axis control and three slide-admission cases bound the behavior. The labelled late-direction mutation changes 14 of 18 force rows; the labelled lost-slide mutation changes exactly the two close-slide rows. Neither mutation is original evidence. Verification requires original output to match the frozen fixture byte-for-byte.

## Public measurement and scope

The test authors speed 36, acceleration/braking 90 and turn rate 3600 degrees/sec. A warm empty tick makes the measured movement due at frame 1. It checks raw and rebound scalar bits, unique template/locomotor admission, pristine health, mass one, uncapped goal speed, zero pivot/wander, zero entry velocity/acceleration, no shadow/coupled authority, no path/worker job/weapon/containment/collision/bounce/held/freefall/stun writers, surviving target/motive state and exactly one measured fixed tick. No admitted locomotor fields are repaired.

The slide cases author 1000 milliseconds, check the admitted approximately 30-frame factor, and use the public ultra-accurate setter. The close slide retains entry yaw and diagonal force; flag-off and far controls turn and use entry force. Default friction and the ultra setter's extra 0.5 friction remain active and are checked explicitly.

Independent yaw/direction comparisons precede the force assertion. Exact baseline entry/request and final heading observations are frozen before changing production, then compared exactly with the candidate. Their fixed 2e-6 tolerance against supplied original headings accommodates existing matrix/trigonometric representation. Expected forces always come from the pre-existing original fixture, never candidate motion.

The later physics stage records friction in `previous_acceleration`; under the asserted admission and no-other-writer guards, final planar velocity minus that snapshot reconstructs marched XZ velocity. The test checks the separate lateral-friction decomposition and actual planar displacement equals marched velocity times dt. The force tolerance is 3e-5 host speed units and position tolerance is 2e-5. Y is not reconstructed. This is original-backed force-stage evidence through the actual host scheduler, not full original frame-phase, nonzero-speed, save/load or trajectory parity.

## Executed boundary

The accepted production baseline at `251a5a6f41daef21c2085b4fae2deeee1c00fd88` passed the nonzero axis control, close-slide control and all-nine independent heading/admission control, and failed the seven intended force comparisons. Every failure was the original-adapted marched X comparison; the smallest distinguishing component gap was approximately 0.4024 host speed units, over 13,400 times the fixed 3e-5 tolerance. The public test and original fixture were unchanged between baseline and candidate.

The candidate passed all ten focused tests, all 82 adjacent movement tests and 27 deterministic/save/experience controls: 119 passed, zero failed and one pre-existing ignored alliance-save test. Default-feature, offline, locked, single-job public integration builds rebuilt the Main library and focused executable for both baseline and candidate; source and executable identities were retained independently of Cargo's mutable cache. Independent review replayed both retained executables and confirmed the intended red/green results. All 27 baseline entry/request/result heading records matched the candidate exactly. Maximum force-stage component error against the frozen original host adapter was 2.384185791015625e-7; position-step residual was at most 1.55e-6.

The 18-row oracle replayed byte-identically, including from a clean source-only copy without Git. Source, manifest, fixture and generated-output drift rejection controls passed. Scoped Rust 2024 formatting, whitespace, LOC and unsafe ratchets passed with unchanged allowlists. The public integration build supplied native Main type-checking. A redundant separate `cargo check --lib` was stopped when it began a separate dependency graph; it supplied no additional check result. `bd` was unavailable, so no issue mutation was possible. Monolithic/internal tests, retail gameplay, full original trajectories and WASM were not run.
