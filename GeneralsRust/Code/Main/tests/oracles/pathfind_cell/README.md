# Pathfinding cell admission oracle

Run `python3 GeneralsRust/Code/Main/tests/oracles/pathfind_cell/oracle.py` from the repository root. The script verifies the pinned SHA-256 of `AIPathfind.cpp`, extracts its unchanged `PathfindCell::setTypeAsObstacle` body, compiles it with a C++17 compiler, and compares its 21 output rows with `expected.txt`. Use `--write` only after reviewing an intentional update to the original source and pin.

The harness supplies the object, body, cell-info allocator and cell position. It exercises the original admission method for every cell type and absent, healthy, and rubble bodies. Each row is `initial_type body_mode accepted final_type obstacle_id`, where body mode 0 is absent, 1 is healthy, and 2 is rubble. The Rust integration test maps the supplied body mode to the classifier’s explicit rubble flag and compares those rows against the production footprint classifier at a selected cell. A separate Rust test checks that the boundary classifier derives rubble from a live object's body state; it is not an original-engine execution. The oracle does not execute the original pathfinder, terrain, wall, object scheduler, or boundary switch; those remain separate verification obligations.
